# C11 Contract — The Gradient Has a Memory

## Identity

**Unit ID:** C11
**Act:** Act II — Dynamics of optimization
**Working title:** The Gradient Has a Memory
**Student transformation:** After this chapter, the reader can orient JVPs and
VJPs by shape, derive reverse accumulation on a DAG with fan-out, identify the
primal state each local pullback needs, and design a checkpoint schedule whose
memory and recomputation costs are explicit.

**Thesis:** Reverse mode makes a scalar gradient cheap in arithmetic by reusing
the forward computation, but that reuse has a retained-state price. The
gradient algorithm is therefore a state-management problem as well as a chain
rule.

## Opening phenomenon

Use the six-node scalar DAG
(a=xy, b=a+x, c=ay, \loss=bc\) at (x=2,y=3). The shared node (a)
receives cotangent contributions (18) and (24). Summing them yields
(\partial\loss/\partial x=144) and
(\partial\loss/\partial y=132); a last-writer-wins implementation returns
(90) and (96).

**Prediction:** Why must the backward pass add at a shared node, and which
forward values must still be available when the local pullbacks execute?

**Phenomenon ID:** `c11-gradient-memory`
**Hardware class:** (a), laptop-CPU reproducible.

## Causal chain

1. **Problem:** A local-derivative table is insufficient on a DAG: fan-out
   creates multiple downstream contributions, while local pullbacks require
   values created earlier in the forward execution.
2. **Instrumentation:** Record a topological tape with node values, parent
   indices, local derivatives, cotangents, retained-state units, and local
   operation counts.
3. **Diagnosis:** Reverse mode is dynamic programming on the transposed
   dependency graph. Arithmetic reuse requires adjoint accumulation and access
   to selected primal state.
4. **Theory:** Derive JVP/VJP orientation, prove reverse accumulation on a DAG,
   compare sweep counts for a full Jacobian, and prove the square-root tradeoff
   for one declared uniform chain-checkpoint model.
5. **Solution:** Use an autodiff contract: input/output shapes, requested
   product, local pullbacks, cotangent accumulation, retained primals,
   recomputation schedule, precision of reductions, and hardware cost model.
6. **Audit:** Reverse mode is not numerical differentiation, not symbolic
   expansion, not memory-free, and not always cheaper than forward mode;
   checkpoint operation counts are not wall-clock predictions.

## Theory and theorem ledger

### `thm-c11-reverse-dag`

- **Phenomenon explained:** `c11-gradient-memory`
- **Assumptions:** a finite scalar-output DAG in topological order, differentiable
  local scalar operations, and stored local derivative values from one realized
  forward execution.
- **Conclusion:** initializing the output cotangent to one and traversing nodes
  in reverse topological order with
  \(\bar v_i=\sum_{j:i\to j}\bar v_j\,\partial v_j/\partial v_i\)
  yields every derivative of the output with respect to a node.
- **Proof mode:** full proof by reverse induction and the multivariate chain
  rule.
- **Diagnostic corollary:** a node with multiple consumers must add all incoming
  cotangent contributions before propagating farther backward.
- **Boundary:** nondifferentiable primitives require an explicit generalized or
  surrogate rule, and floating-point sums need not be order invariant.
- **Source:** standard reverse-mode AD; Baydin et al.

### `thm-c11-jvp-vjp`

- **Phenomenon explained:** `c11-gradient-memory`
- **Assumptions:** a differentiable map
  (f:\mathbb R^p\to\mathbb R^q\) at a fixed point with Jacobian
  (J\in\mathbb R^{q\times p}\).
- **Conclusion:** one forward tangent sweep evaluates (Jv); one reverse
  cotangent sweep evaluates (J^{\mathsf T}u\). Materializing the complete
  Jacobian by basis seeds requires (p) forward sweeps or (q) reverse sweeps.
- **Proof mode:** full derivation from columns and rows of the Jacobian.
- **Diagnostic corollary:** a scalar output has (q=1), so one reverse sweep
  returns its full gradient with respect to all (p) inputs.
- **Boundary:** sparsity, batching, higher derivatives, local-operation costs,
  retained state, and parallel execution can change the best implementation.
- **Source:** Baydin et al.; arithmetic-circuit context from Baur and Strassen.

### `thm-c11-uniform-checkpoint`

- **Phenomenon explained:** `c11-gradient-memory`
- **Assumptions:** a chain of (L) equal-size states and equal-cost local
  transitions, with (k\mid L); retain every (k)-th boundary state and, during
  the backward pass, reconstruct and retain one block's missing interiors.
- **Conclusion:** peak retained state is (L/k+k) units, extra forward
  evaluations are (L-L/k), and the peak-state expression is minimized at
  (k=\sqrt L) when the square root is integral.
- **Proof mode:** full counting proof plus AM–GM.
- **Diagnostic corollary:** for (L=64,k=8), the declared schedule reduces the
  peak from (65) stored states to (16) while adding (56) local forward
  evaluations.
- **Boundary:** this is not a globally optimal schedule for arbitrary DAGs,
  heterogeneous tensors, communication, or a measured runtime model.
- **Source:** model derivation in this chapter; Chen et al. for sublinear-memory
  checkpointing.
