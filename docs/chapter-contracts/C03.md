## Thesis and transformation

**Thesis:** A dtype name is not a numerical contract. A prediction about
training arithmetic must state where values are stored, where operations are
performed, where reductions accumulate, how results round, and which local
spacing and range apply at the values actually encountered.

**Student transformation:** After this chapter, the reader can classify an
impossible or stalled result as a range, representation, arithmetic,
cancellation, or resolution-allocation failure; calculate the local grid that
causes it; and prescribe a repair matched to that failure.

## Opening phenomenon

Use a deterministic CPU witness:

- initialize a stored FP16 scalar at \(1024\);
- request the update \(+0.25\), then round back to FP16 after every step;
- repeat for 400 steps;
- compare deterministic round-to-nearest with an exact FP64 trajectory;
- use seeded stochastic rounding only after the deterministic failure has
  been diagnosed.

At \(1024=2^{10}\), adjacent FP16 normal values are one unit apart. The
requested update is below half that gap. Repeated deterministic storage
therefore returns \(1024\) on every step instead of the exact endpoint \(1124\).
This is class (b): CPU simulation of a declared format, not CPU timing offered
as accelerator performance.

## Prediction and competing explanations

Ask which of these failed before naming unit roundoff:

- **range:** the exact value lies outside the finite format;
- **input representation:** the requested increment is lost before arithmetic;
- **arithmetic rounding:** the sum is formed and then rounded back to the old
  stored value;
- **cancellation:** subtraction exposes input errors relative to a much
  smaller result;
- **accumulation:** a reduction uses an insufficient working format;
- **dynamics:** the mathematical update is genuinely zero or equilibrated.

The opening controls eliminate range and mathematical equilibrium. C02
supplies the cancellation/input-representation distinction that C03 must now
quantify.

## Theory commitments

### `thm-c03-binade-spacing`

- **Phenomenon explained:** the \(0.25\) update at \(1024\) vanishes.
- **Assumptions:** a normalized radix-two format with \(p\) significand bits.
- **Conclusion:** values in \([2^e,2^{e+1})\) have spacing
  \(2^{e-(p-1)}\); round-to-nearest changes a representable value only when
  an update crosses the local midpoint, aside from tie handling.
- **Proof mode:** full proof from the normalized representation.
- **Diagnostic corollary:** global “decimal digits” are less useful than
  \(\operatorname{ulp}(x)\) at the current state.
- **Boundary:** subnormals, overflow, signed zero, and exceptional values need
  separate clauses.
- **Source:** IEEE 754 terminology; derivation in the chapter.

### `thm-c03-cancellation`

- **Phenomenon explained:** C02 obtains \(-\operatorname{ulp}(\mu^2)\) from
  two individually plausible rounded moments.
- **Assumptions:** represented operands
  \(\widehat{x}=x(1+\delta_x)\),
  \(\widehat{y}=y(1+\delta_y)\), with a nonzero exact difference.
- **Conclusion:** the relative error in the represented difference contains
  an amplification factor comparable with
  \((|x|+|y|)/|x-y|\).
- **Proof mode:** full proof.
- **Diagnostic corollary:** wider subtraction cannot recover low bits already
  lost while forming or storing its operands.
- **Boundary:** the result is a data-sensitivity statement, not a complete
  kernel-level forward-error bound.
- **Source:** Higham; independently derived.

### `thm-c03-stochastic-rounding`

- **Phenomenon explained:** repeated sub-grid updates stagnate under
  deterministic rounding but move in expectation under randomized adjacent
  rounding.
- **Assumptions:** \(a<x<b\) are adjacent grid points and rounding selects
  \(a\) with probability \((b-x)/(b-a)\), \(b\) otherwise.
- **Conclusion:** the rounded value has expectation \(x\), with error variance
  \((x-a)(b-x)\).
- **Proof mode:** full proof plus seeded model calculation.
- **Diagnostic corollary:** stochastic rounding removes the deterministic
  drift of one rounding event; it does not make a trajectory exact.
- **Boundary:** unbiased local errors may be dependent through state and do not
  prevent overflow, poor scaling, or algorithmic instability.
- **Source:** Connolly, Higham, and Mary (2021).

## Diagnostic sequence

1. **Expose the local grid.** Derive binade spacing and distinguish machine
   epsilon from unit roundoff and \(\operatorname{ulp}(x)\).
2. **Map the range.** Produce the format envelope from `numpy.finfo`; separate
   smallest normal from smallest subnormal.
3. **Declare the execution path.** Treat storage, compute, accumulation, and
   output as separate roles. A format table alone is insufficient.
4. **Harvest C02.** Explain why its \(-32\) is exactly one local ULP and why
   wider subtraction cannot repair already-rounded raw moments.
5. **Allocate resolution.** Show one global symmetric quantization scale
   collapsing small coordinates in the presence of an outlier, then repair
   with declared blocks.
6. **Change the rounding rule.** Use stochastic rounding as a scoped cure for
   deterministic sub-grid stagnation, not as a general low-precision cure.
