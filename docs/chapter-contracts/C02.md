## Thesis and transformation

**Thesis:** A useful streaming state is not merely small; it preserves the
right invariant, avoids the dominant floating-point hazard, and admits the
combine rule demanded by the execution schedule.

**Student transformation:** After this chapter, the reader can diagnose and
repair a one-pass variance calculation because they understand centered
state, the Welford invariant, and the pairwise correction that makes partial
states mergeable.

## Opening phenomenon

Use one seeded CPU witness:

- draw 200,000 standard-normal deviations with seed 6210;
- add offset 20,000;
- cast to FP32 before every comparison;
- compute the population variance three ways:
  naïve one-pass raw moments, centered two-pass, and sequential centered state;
- use FP64 only to evaluate the same represented FP32 inputs.

The naïve method returns a negative population variance under the pinned
environment. The centered methods return a value close to the FP64 reference.
A negative variance is the symptom, not yet the diagnosis.

## Prediction

Before showing results, ask:

1. Which method fails first as the common offset grows?
2. Is the failure caused by FP32 input quantization, the denominator, or a
   subtraction between large nearby raw moments?
3. Can one state be both one-pass and mergeable?

## Competing explanations

- **Input representation:** the FP32 cast may already erase small deviations.
- **Algorithmic cancellation:** the raw-moment identity subtracts two
  quantities of order \(\mu^2\) to recover one of order \(\sigma^2\).
- **Accumulation roundoff:** long sums round even without final
  cancellation.
- **Statistical convention:** population \(n\) versus sample \(n-1\) changes
  the target but cannot create a negative exact variance.
- **Random fluctuation:** the sample variance differs from one, but cannot
  explain a large negative result.

The control must separate these.

## Theory

### Full-proof commitments

1. **Online mean recurrence**
   \[
   \mu_n=\mu_{n-1}+\frac{x_n-\mu_{n-1}}{n}.
   \]
2. **Welford invariant**
   \[
   M_{2,n}=\sum_{i=1}^{n}(x_i-\mu_n)^2,
   \qquad
   M_{2,n}=M_{2,n-1}
      +(x_n-\mu_{n-1})(x_n-\mu_n).
   \]
3. **Pairwise/Chan merge**
   \[
   M_{2,A\cup B}=M_{2,A}+M_{2,B}
   +(\mu_B-\mu_A)^2\frac{n_A n_B}{n_A+n_B}.
   \]
4. **Exact-arithmetic associativity:** each valid state represents the
   sufficient triple for its underlying multiset, so either parenthesization
   of disjoint unions yields the unique count, mean, and centered sum of
   squares of the union.

### Diagnostic corollaries

- The raw-moment formula is ill-conditioned with respect to relative errors in
  its two large terms when \(|\mu|/\sigma\) is large.
- Centered state avoids that dominant subtraction but does not recover
  distinctions lost in the input representation.
- Exact associativity exposes a tree reduction; floating-point parenthesization
  can still change final bits.

Every theorem block must declare the opening phenomenon it explains.

## Repair

1. Carry \((n,\mu,M_2)\).
2. Update it with centered deviations for a sequential stream.
3. Merge disjoint states with the between-group correction.
4. Choose population or sample denominator only after the centered sum of
   squares is available.
5. Treat two-pass centered variance as a valid baseline when the data is
   revisitable; do not claim it is universally the production kernel.

## Audit and boundary

- **Same-input control:** FP64 reference is computed after the FP32 cast.
- **Shift control:** add a constant in exact arithmetic; variance should not
  change, while the naïve floating-point result degrades.
- **Representation boundary:** increase the offset until FP32 can no longer
  represent unit-scale deviations; centered state must then degrade too.
- **Merge control:** compare sequential state with balanced and left-fold
  merges. Exact formulas agree; floating-point last bits may not.
- **No hardware overclaim:** CPU timing is not used to claim accelerator
  performance.
