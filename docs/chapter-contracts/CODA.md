# Coda contract — One Spike, Four Suspects

## Opening phenomenon

One engineered training run spikes by more than sixty-fold at a known step,
while precision, curvature, estimator/data, and implementation state all
remain initially plausible explanations. Update geometry and normalization
state are separate controls on the implementation suspect.

## Diagnostic chain

Hold data order and incident fixed; pair float32 with float64; compare top and
directional curvature with the fixed boundary; decompose gradient discrepancy
against the estimator target; inspect update versus weight spectra; verify
repeated input-statistic state; reveal the engineered target shift only after
the rivals have been tested.

## Evidence

- `coda-incident-001`, class (a), hash-seeded 120-step paired training incident
  with a content-addressed C17 harness pin.
- The Coda introduces no theorem. It applies C03 and C12–C17 as instruments.

## Boundaries

This is a designed differential-diagnosis exercise, not evidence that target
shifts explain loss spikes generally. A benign control acquits only the tested
mechanism at the observed scale. The Coda is unnumbered and closes the core;
it does not silently open Act III.

## Terminal capability

The reader completes one incident-report card that names estimator target,
precision contract, curvature boundary, spectral evidence, state replay, the
discriminating control for each suspect, and the surviving cause.
